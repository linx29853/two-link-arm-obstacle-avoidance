## 问题与预测

- **问题：** 能否跳过 RRT 路径中的多余姿态，同时保留避障所需的中间姿态？
- **预期：** 当前起终点直连已通过检查，20 节点路径可以简化为 2 节点；直连失败的路径应保留必要绕行。
- 学习者已解释：端点不变但路线改变，需要重新检查；捷径失败不表示原路径无效。绕障案例的具体结果由 AI 代验证，不补写成学习者独立预测。

### 简化策略

输入为已验证有效的弧度姿态列表。结果先保存起点，再从当前节点开始，按后续索引从远到近检查连接，选取第一条有效候选；全部非相邻候选失败时，保留原相邻边。重复直到终点。输出保存姿态副本，不修改原路径。

每条候选按最大关节变化量决定采样数量：

```text
delta = max(abs(q_to - q_from))
sample_count = max(2, ceil(delta / deg2rad(1)) + 1)
```

每个关节的相邻检查间隔不超过 1°；这不是二维角向量的欧氏步长。当前首尾最大变化 150°，使用 151 点；不能对长捷径固定使用 11 点。复核简化后的连接也按同一公式计算采样数。

指标：节点数、各段关节角欧氏距离之和（rad）、端点保持和连接采样结果。没有测运行时间。

## 修正与理解

- 最初顺序检查并逐点添加，无法减少路点；改为优先连接最远后续姿态。
- 空路径检查移到读取 `path[0]` 之前。
- 采样与验碰原先留在旧循环，新循环误用旧的 `direct_valid`；移入候选循环后，每条捷径都重新检查。
- `main()` 原先只有直连通过才调用简化，直连失败无法尝试部分捷径；现改为直接调用通用函数。
- `break` 结束本轮候选检查，`i = next_index` 推进当前保留节点，输出使用 `.copy()`。
- 原相邻连接作为保底不再检查，因此“输入路径已有效”是前提，不能依赖此函数修复无效输入。
- 该贪心策略不保证全局最优或最少节点，也不保证运动平滑、速度及加速度限制。有限采样不构成连续安全证明，未增加工程安全裕量。
- 当前接口以姿态列表、正的 `max_angle_step` 为前提，通用输入校验及多场景评测尚未完成。
- 下一步按加速安排进行 MuJoCo 路径预览，随后学习时间缩放、约束与动力学跟踪；预览不算控制验收。
